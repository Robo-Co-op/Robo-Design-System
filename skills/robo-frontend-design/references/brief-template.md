# Compact Robo frontend brief

Use as a working note, not a form to send unless multiple details are truly required.

| Field | Record |
|---|---|
| Product / page | What is being made or changed? |
| Brand | robo-coop / robo-lab / coop-lab / robo-university |
| Theme | light / dark / existing |
| Audience | Who is using it? |
| Primary job | What must the user accomplish? |
| Content | Actual headline, CTA, features, data and constraints |
| Screens / states | Routes and loading / empty / error / success |
| Technical context | Existing app, components, framework and constraints |
| Evidence | Screenshots, brand references, user tests, source |
| Review | Mobile + desktop screenshots and accessibility checks |

## Example: Robo Lab light client-facing page

- Brand: `robo-lab`; theme: `light`.
- Use canonical light semantic tokens in `tokens/brands/robo-lab.json`; avoid recreating a new "light blue" palette.
- Primary job: make a technical service understandable and encourage a specific next action.
- Visual signature: an accurate system diagram or real product interaction rather than ornamental futuristic UI.
- Typography: Roboto / Noto Sans JP from `tokens/core.json`.
- Acceptance: working responsive interface, grounded copy, visible focus, realistic state handling and screenshot review.
